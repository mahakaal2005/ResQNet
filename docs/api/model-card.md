# Detection model card — resqnet-person-v1

Owner: Faiqua (AI/CV — Detection). This documents the first real fine-tuned
weight file committed to the repo, replacing the pure color-segmentation
`CandidateDetector` as the default when weights are present (`app.py`,
`pipeline.py` auto-select; see `RESQNET_DETECTOR` env var / `--detector` flag
to force either one).

## What this is

- **Base model**: YOLOv8n (`ultralytics`, nano — smallest/fastest variant)
- **Fine-tuned on**: [VisDrone2019-DET](https://github.com/VisDrone/VisDrone-Dataset)
  (Tianjin University), `pedestrian` + `people` classes remapped to a single
  `person` class — matching this project's actual scope (detecting survivors,
  not classifying vehicle types VisDrone also labels)
- **Training subset**: 700 train images / 120 val images, randomly sampled
  (seed 42) from VisDrone's full 6,471/548 train/val split — capped for
  CPU-only training time, **not** the full dataset
- **Training config**: 25 epochs, imgsz 416, batch 16, CPU (no GPU was
  available on the training machine — see repo history for the Secure Boot /
  driver conflict that blocked GPU access)

## Honest scope — read before trusting this number

This is a **Phase 1 baseline demonstrating a real, working fine-tuning
pipeline** (real dataset, real training run, real held-out validation) —
**not** a production-grade detector. Specifically:

- Trained on ~11% of VisDrone's available train images (700 of 6,471) and
  fewer epochs than a production run would use, to fit CPU-only training time
- VisDrone is daylight, high-altitude, generally clear-visibility drone
  footage — not validated against occlusion, low light, or water/flood
  scenes specifically relevant to this project's disaster-response use case
- No test-time augmentation, no ensemble, no post-training calibration

## Real numbers

See `apps/ai-service/validation_results.json` for the actual precision/recall
from `scripts/run_real_evaluation.py`, run against the 120-image held-out
VisDronePerson val split (never seen during training) — generated by
`src/training/evaluate.py`'s IoU-matching (threshold 0.5), the same evaluator
this repo already had, just fed real data for the first time.

## Reproducing / improving this

```bash
cd apps/ai-service
python -m pip install ultralytics
python src/training/train.py --data /path/to/VisDronePerson/dataset.yaml \
    --model yolov8n.pt --epochs 25 --imgsz 416 --device cpu
# or --device 0 once GPU access is fixed -- see repo history for the
# Secure Boot MOK enrollment steps that were blocking it
python scripts/run_real_evaluation.py
```

To do better than this baseline: train on the full VisDrone split, more
epochs, a GPU (once available), and ideally add domain-specific
aerial/flood-scene images per the PRD's Data & AI Strategy (public dataset +
self-collected + synthetic augmentation + held-out validation).
